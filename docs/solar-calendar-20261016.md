# 节令日历接入记录（2026-10）

> **抓包版本**：`1.15.0.2_20261001`
> **现状**：功能在线，节令内容随服务端配置变化，不依赖本地年份表

## 一、服务与入口

独立服务 `SolarTermsV2Service`，**不替换**旧节令活动接口。入口在「分析」与「游戏商城」之间。

日历按季度展示，一节令一行卡片：日期、官方描述、奖励、领取状态；窄屏把奖励移到内容下方。季度与节令日期**不附加年份**，开放/结束时间全部取服务端响应，不用本地固定年份判断资格。历史节令仍可查看标题、描述、奖励与已领取/已过期状态。样本含 13 个节令、3 个季度。

## 二、实现要点

- 标题、题目、选项、规则取自官方 `SolarTerms` / `SolarSeason` 配置；农历与诗句由官方描述图片逐项核对后转写成文字，**只使用已有物品图标**，不提交描述图或场景图
- 官方 `answer_index` 是**零起始**，经范围校验后以 `answerIndex` 返回，弹窗在对应选项旁标「正确答案」；缺失或越界则不标。用户仍要手动选择提交
- 领取/答题前重新拉服务端状态，核对开放窗口、已领取、当日答错限制、错误选项、题目是否变化；写操作串行，不自动重提
- 页面在开放、结束、答错次日这三个边界刷新状态；账号切换时关闭弹窗并丢弃旧请求
- 写成功但刷新失败：保留实际奖励并提示刷新，**不要提示再次领取**

## 三、同期修正的图鉴字段

按官方编码器改了字段名与类型，关键是**把"奖励"和"增益"分开读**：

| 字段 | 含义 |
| --- | --- |
| 等级门槛 | 第 N 级的进度要求 |
| `can_claim` | 是否可领 |
| `claimed` | 是否已领 |
| 实际奖励 | 领取后拿到的物品 |
| 增益 | 加成，之前被误当成奖励展示 |

收藏奖励列表展示当前进度、每级所需进度、真实领取状态；进弹窗定位到首个未领取档位，列表滚动、按钮固定。自动领取同步适配新字段。

## 四、同期修正的奶茶两处

- 雇佣与「我的工作」同时显示**绝对结束时间和** `剩余 HH:mm`
- 一键制作只选已解锁配方对应的非锁定、正数量果实堆叠，提交前展示全部消耗；服务端仍逐项检查 UID 与数量，**不循环制作、不自动重试**

## 五、验证边界

离线验证覆盖：历史节令、未开放/已开放/已过期、错误选项、每日答题次数、重复领取、成功后刷新失败、账号切换。

当时实服重阳与霜降尚未开放，样本图鉴已领至当前等级，新领取与答题接口是按官方编码器 + 模拟响应验证的，**未宣称实服成功**。

## 六、经验

1. 零起始索引要校验范围，越界宁可不标也不猜
2. 奖励与增益是两个字段，混读会导致面板数字翻倍
3. 时间窗口一律取服务端，不在本地按年份硬算
