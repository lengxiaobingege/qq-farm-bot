# 牧歌初启（2026-11-17 牧场限时活动）

> 本文记录「牧歌初启」活动的协议结构、移植来源与自动化实现。活动周期 11-17 10:00 ~ 11-30 23:59，
> 主活动 id `2026111700`，是**牧场专属活动**（靠 id 前缀 `20261117` + uid `MugeMainUI` 归类，见 [ranch.md](ranch.md)）。

| 模块 | 子活动 id | 玩法 | 对应协议字段 |

| 牧友同行 | `2026111703` | 拥有一定数量已开牧场好友可领奖（解好友不影响已计数） | `MugeInviteFriend` (f125) |

## 2. 协议（`core/src/proto/muge.proto`）

协议定义参考了同期实现（提交 `ea22f0c`），其结构与只读探测器实测的 f124-127 完全吻合，
状态字段 `status` 语义经实测确认：

| status | 含义 |
| --- | --- |
| 1 | 未达标 / 未解锁 |
| 2 | **可领取** |
| 3 | 已领取 |
| 4 | 进行中 / 未解锁 |

领奖走 `ActivityService.Operate`，请求 `MugeOperateRequest`（`id` + `cmd` + 专属字段），命令号：

| 操作 | cmd | 字段 |
| --- | --- | --- |
| 领成长手册任务 | 82 | task_claim |
| 领成长手册章节档位 | 83 | task_tier_claim |
| 领牧友同行档位 | 84 | invite_friend_tier_claim |
| 领兴牧庆典档位 | 85 | global_count_claim_tier |
| 保存人格答题 | 86 | survey_save_progress |
| 人格结算 | 87 | survey_settle |
| 领首次分享奖励 | 89 | survey_claim_share_reward |

数据读取走空的 `ActivityListRequest`（ActivityList 是场景无关的全站流）→ `MugeListReply`，再按活动 id 过滤出牧歌分组。

## 3. 接入范围（最小改动，不动 WASM）

同期实现 `ea22f0c` 一次改了 400+ 文件（含 UI 大重构、其他活动、TSDK WASM 升级）。本次**只挑牧歌相关、不碰 WASM 和客户端版本**——
已实测当前版本能正常收发 muge 数据（协议 body 是 protobuf，与底层加解密 WASM 无关），故无需冒险升级。

## 4. 自动化策略（`muge-auto.ts`）

挂在现有 `activity_task` 自动化开关下，每 tick 串行执行：

- 自动领取 **status=2** 的：兴牧庆典档位、牧友同行档位、成长手册任务、成长手册章节档位；
- **不做**人格测试/分享（主观操作 + 社交分享，交用户手动）；
- 复用 muge-activity 的回包确认 + 防重复提交，单步失败用 `safeStep` 隔离、不刷屏。

实测验证（2026-11-17 22:20）：自动化一轮自动领取兴牧庆典 7 档 + 牧友同行 6 档，领后所有可领项 status 变 3（已领取）。

## 5. 用户操作入口

牧场 → 活动页 → 「牧歌初启」卡片 → **查看活动详情**（跳转 `?activity=muge`），可看奖励进度、做人格测试。
日常领奖由自动化静默完成，无需手动点。
