## 产品简介

### 它是什么

一个部署在您自己服务器上的农场自动化助手，由两部分组成：

- **core 后端**：以子进程 Worker 隔离运行每个游戏账号，通过微信小游戏协议与服务器通信，执行挂机策略
- **web 面板**：Vue 3 单页应用，由后端托管，提供账号管理、策略配置、实时状态与日志查看

### 能做什么

| 能力 | 说明 |
| --- | --- |
| 多账号挂机 | 每个账号独立进程运行，互不干扰；掉线自动重登；支持抓包 Code 与微信扫码两种登录方式 |
| 农场自动化 | 收获、种植、浇水、除草、除虫、施肥、土地升级全流程自动化，策略可按账号配置 |
| 好友自动化 | 偷菜、帮忙、捣乱合并为单次访问，支持黑名单、安静时段与互动上限 |
| 活动自动化 | 奶茶热销中、快乐不独享、节令日历等活动的全流程自动化，单步容错，详见[活动自动化](#活动自动化) |
| 经营分析 | 作物收益分析、策略预览、背包估值、商城与神秘商人价格查询 |
| 事件推送 | 基于 pushoo 的实例级通知，掉线与关键事件第一时间知晓 |

### 适用场景与边界

适用于拥有 QQ 农场微信端账号、希望减少重复操作的个人用户。本项目不提供多用户体系，不适合作为多人共用服务对外运营。

> [!WARNING]
> 本项目仅供学习与研究用途。使用本工具可能违反游戏服务条款，由此产生的一切后果由使用者自行承担。

## 快速开始

### 环境要求

| 运行方式 | 要求 |
| --- | --- |
| 源码运行 | Node.js 20.19 或以上、pnpm 10 或以上 |

推荐通过 Corepack 启用项目指定版本的 pnpm：

```bash
corepack enable
pnpm --version
```

### 步骤一：获取并构建

```bash
git clone https://github.com/lengxiaobingege/qq-farm-bot.git
cd qq-farm-bot
pnpm install
pnpm dev
```

`pnpm dev` 会先构建前端，再启动后端。Windows、Linux、macOS 均可使用。

### 步骤二：登录管理面板

1. 服务首次启动只创建管理员账号 `admin`，密码为空。
2. 浏览器打开 `http://localhost:5173`（开发模式）或 `http://localhost:3007`（后端托管模式），登录页自动切换为「首次使用 · 设置管理员密码」。
3. 自行输入密码并确认；也可以单击「生成随机密码」按钮生成 16 位强密码并自动填入，生成后请立即保存或复制。
4. 提交后自动登录进入面板。

密码要求：至少 8 位，且包含大写字母、小写字母、数字、特殊符号中的至少 3 类。

### 步骤三：添加游戏账号

1. 进入设置页，添加游戏账号（微信扫码或抓包 Code 登录）。
2. 启用账号，系统为其启动独立 Worker。
3. 在自动化配置中勾选农场、好友、活动等策略。

### 步骤四：验证运行

1. 面板概览页应显示账号在线状态与角色 ID。
2. 实时日志应出现任务调度记录（如收获、种植、活动任务）。
3. 如配置了事件推送，手动停用账号网络应能收到掉线通知。

### 后台常驻运行（Linux）

```bash
bash ./start.sh              # 缺依赖或代码变化时自动安装并增量重建
bash ./start.sh --rebuild    # 忽略缓存完整重建
tail -f app_dev.log          # 查看日志
bash ./stop.sh               # 停止服务
```

### 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 扫码登录后不久掉线 | 系统会自动通过 refreshToken 或 openid + accessToken 重获会话；若持续掉线，重新扫码即可 |
| 管理员密码遗忘 | 属服务器运维操作，需要文件系统访问权限，流程不在公开文档中说明，请妥善保管密码 |
| 端口被占用 | 后端端口 `3007` 可在运行配置中调整；前端开发服务器端口由 Vite 自动处理 |
| 活动自动化没有执行 | 确认设置页「活动任务」自动化开关已启用；活动结束后对应条目会自动静默 |
| 想看某次协议交互细节 | 参考[项目文档](#项目文档)中对应专题文档与 tools 目录下的抓包分析脚本 |

## 功能说明

### 活动自动化

活动自动化代码位于 `core/src/services/activity-auto/`，每个活动一个独立文件，由调度器串行编排，避免并发请求触发网关限速。设计要点：

- **单步容错**：任一步骤失败（例如货币不足）只跳过该步骤，不中断整轮
- **错误去重**：同一活动的同一错误 30 分钟内不重复写日志，避免活动结束时刷屏
- **过期静默**：活动结束后对应自动化自动停止，不产生无效请求

| 活动 | 自动化流水线 |
| --- | --- |
| 奶茶热销中 | 领取收银台收益与工资 → 按店铺等级工位上限补雇员工（24 小时 → 12 小时 → 4 小时阶梯降档，有多少花多少）→ 加速收银台 → 升级店铺 → 制作饮品 → 涨薪互动 → 成长基金解锁与领取 |
| 快乐不独享 | 每日快乐值、每日首次分享、可领档位奖励 |
| 节令日历 | 节令开放当天自动执行一次（按北京时间记账）：领取奖励、本地题库答题（带题目变化防呆）、季度累计奖励 |

### 农场自动化

- 自动收获、种植、浇水、除草、除虫、铲除与土地升级
- 自动施肥、多季作物补肥、指定土地类型施肥、化肥自动购买
- 一键务农、种植、收获、铲除、全收等面板快捷操作
- 多套种植策略、背包种子优先级、作物黑名单与执行间隔可按账号配置
- 任务、免费礼包、分享奖励、会员礼包、月卡礼包、图鉴奖励等每日状态汇总，按天自动领取

### 好友互动

- 自动访问好友、偷菜、帮忙浇水、除草除虫、放草放虫
- 巡查合并为单次访问：每位好友只进一次农场完成全部互动
- 好友上场宠物按天缓存，后台每日分批补齐，"护主犬经验满仍帮忙"不再逐个试探
- 好友黑名单、安静时段、互动经验上限、按 GID 批量维护与互动记录查询

### 图鉴与藏品

- 作物图鉴与超变图鉴的等级、进度、果实收藏状态一站式查看
- 超变图鉴依据 `Illustrated.json` 的 `param`/`type` 字段区分黄金果实、活动果实与装扮果实，不依赖名称推断
- 超变属性弹窗汇总当前生效加成与等级达成明细，移动端四列布局自适应

### 背包与交易

- 背包物品使用、出售与批量出售，按活动区间与过期时间智能判断可售状态
- 神秘商人活动商品、游戏商城价格折扣限购与购买
- 种子、果实、道具与作物收益数据查询

### 活动中心

- 活动列表协议统一展示当前与已结束活动；快照请求串行合并，避免占满游戏网关请求队列
- 千星游记（赛季通行证）、观星礼录（星座点亮）、星砂商店（兑换）、节令活动、鹊桥寄情（筑桥与赠礼）、雨落成诗（天气瓶与气象研究）等玩法页面

### Web 控制面板

- 概览、个人、活动、好友、分析、神秘商人、游戏商城、设置页面
- Socket.IO 实时状态与日志流，液态玻璃风格界面；PC 固定侧栏，移动端顶部栏与底部导航
- 设置页统一管理游戏账号、自动化策略、运行环境、管理员密码与下线提醒

## 🔐 管理端安全设计

面板不设注册体系，全局仅一名超级管理员，账号固定为 `admin`。本章说明安全机制的设计原理与使用边界。

### 凭据模型

| 阶段 | 触发条件 | 行为 |
| --- | --- | --- |
| 未初始化 | `admin.json` 不存在或标记 `needsSetup` | 登录接口拒绝一切密码尝试，登录页自动切换为「设置管理员密码」表单 |
| 已初始化 | 首次设置完成 | 进入常规登录；设置接口永久失效，无法被再次调用覆盖凭据 |

设计取舍：

- **无预设密码、无默认密码、无后门**。从根上消除"部署后未及时改密"这一最常见的事故窗口，攻击者不存在可以猜的默认值。
- **明文密码永不落盘、不经网络回传**。首次设置时密码仅存在于浏览器到服务器的单次请求中，服务端只保存 PBKDF2 派生哈希（SHA-512、10 万次迭代、32 字节随机盐），此后没有任何命令或接口能读回密码。
- **登录页内置 16 位随机密码生成器**。基于浏览器 `crypto.getRandomValues` 密码学安全随机源，四类字符齐全，剔除易混淆字符 `0O1lI`，生成值自动填入并支持一键复制。
- **密码策略**：至少 8 位，且包含大写字母、小写字母、数字、特殊符号中的至少 3 类，拒绝常见弱口令字典。

### 防爆破与锁定

- 双层限流：每个 IP 每分钟最多 10 次请求；登录失败 5 次锁定该 IP 15 分钟，窗口自动过期清理
- 锁定按 IP 分桶而非全局锁账号：单一来源的暴力尝试不会把账号整体锁死形成拒绝服务，也无法通过更换用户名绕过
- 客户端 IP 经反向代理链路解析，不可伪造
- 登录成功与失败（含来源 IP）全部落日志，可审计

### 哈希与找回

- 旧算法（裸 SHA-256）的存量记录在下次成功登录时透明升级为 PBKDF2，无需手动迁移
- 管理员密码丢失后的找回属于服务器运维操作，需要文件系统级访问权限，具体流程不在本公开文档中说明

### 部署侧加固清单

程序边界之外的安全，需要您在基础设施层完成：

- [ ] 不要将 `3007`/`5173` 直接暴露公网；生产环境使用 Nginx/Caddy 反向代理 + HTTPS，面板路径叠加访问控制（IP 白名单或 Basic Auth）
- [ ] `core/data/` 目录包含账号凭据、会话令牌与运行数据：权限建议 700，纳入备份但绝不提交到公开仓库
- [ ] 定期审计 `core/data/logs/` 中 `admin` 模块日志，关注异常来源 IP
- [ ] 公网部署建议配置实例级事件推送（pushoo），掉线与异常第一时间知晓

## 项目结构

```text
qq-farm-bot/
├── core/                  # Node.js 后端、账号 Worker 与协议实现
│   ├── src/
│   │   ├── controllers/   # Web API 与鉴权路由
│   │   ├── core/          # 单账号 Worker 与任务调度

│   │   ├── services/      # 农场、好友、图鉴、活动、商城、微信登录等业务

│   │   ├── gameConfig/    # 作物、道具、等级、图鉴等游戏配置
│   │   ├── activity-data/ # 活动静态配置与本地题库
│   │   └── models/        # 超级管理员、游戏账号与配置持久化
│   ├── data/              # 运行数据（凭据哈希、账号、日志等，请勿提交）

├── web/                   # Vue 3 Web 面板
│   ├── src/components/    # 农场、图鉴、背包、任务、活动与基础组件
│   ├── src/stores/        # Pinia 状态管理
│   ├── src/views/         # 各功能页面
│   └── dist/              # 前端构建产物
├── docs/                  # 项目专题文档
├── tools/                 # 配置下载、图片下载与协议分析工具
└── pnpm-workspace.yaml
```

## 二创变更摘要

- 移除外部 farm-code 换码 fallback：微信换码仅保留本地 loginBuffer 方式
- 微信登录 buffer 失效自动重获：无 refreshToken 时自动用 openid + accessToken 重获 loginBuffer 再换码
- 移除 QQ 端：仅保留微信扫码与抓包 Code 登录
- 活动自动化重构：`activity-auto/` 按活动拆分独立文件，单步容错与错误 30 分钟去重；奶茶活动支持阶梯雇佣与按工位上限补满
- 管理员凭据加固：首次部署不预设密码，由用户在首次登录页自行设置，支持一键生成 16 位随机强密码；服务端仅存 PBKDF2 哈希，不存任何明文
- 日志时间统一为北京时间（UTC+8）
